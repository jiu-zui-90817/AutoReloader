# INI 工程编辑器 — 长期实践路线

> 定位：工程级 INI 工具（浏览 / 编辑 / 校验 / 变更），与战术工坊（快调 + hotfix）分工，同属 AutoReloader 工具链。  
> 状态：v2.x 已具备工程打开、对象树、CSF 名、保存备份、另存为单节、调试部署、全工程搜索、保存前校验等。  
> **当前主推（2026-10-09）**：**P0 大工程加载性能** → 详见 [`docs/p0-performance.md`](p0-performance.md)。

---

## 1. 产品分工（长期不变）

| 工具 | 职责 |
|------|------|
| **INI 工程编辑器** | 工程结构、全文编辑、引用与校验、变更集、注册/增删 |
| **战术工坊** | 单对象常用字段快调 → 安全写入 `hotfix.ini` |
| **AutoReloader.dll + 启动器** | 游戏内热重载 |

避免两边都做成「半个记事本」；编辑器不重复工坊的表单快调主路径。

---

## 2. 已具备（基线）

- 工程目录 / 单文件；profile（Mental Omega / YR）
- Ares `#include` 合并读取；允许列表内 ini
- 对象树 + CSF 中文对照；合并 / 单文件视图；分类懒展开骨架
- 代码编辑、行号、属性说明（`common_flags`）
- 保存当前 / 全部、自动备份、UTF-8 无 BOM
- 另存为（单节规范化，避免重复 `[ID]`）
- 新增 / 删除（持续打磨）；调试部署 hotfix
- **全工程搜索 + 引用跳转**（A1）
- **保存前校验 linter**（A2）
- 显示名磁盘缓存（fingerprint 失效）
- 与工坊共享 `shared/` 与 schema 唯一源

### 阶段 C — 进阶与宣传点

| 序号 | 能力 | 说明 |
|------|------|------|
| C1 | **依赖关系视图** | 单位→武器→弹头/抛射体（文本树+跳转）；**已做 2026-10-10** |
| C2 | **引擎/扩展键提示** | 原版 / Ares / Phobos 与 schema 绑定（可借鉴织网者字段表） |

### 明确后置 / 不做（除非需求极强）

- 完整 MIX 解密集成（独立工具、社区争议）
- 与工坊重复的「表单改 Strength」主路径
- 超重 CSF 全功能编辑器（易成第二深坑）
- 为性能整编辑器改用 C/C++（DLL 热重载保持 C++ 即可）

## 4. 技术与工程约束

- **Ares 基线**：热重载与编辑器校验默认按 **Ares 可用** 语义理解规则（如 `[GenericPrerequisites]` 别名、点号扩展键、`#include`）。不以纯原版 YR 为唯一规范；未知扩展键宁可不报，避免误杀。
- **共享**：`shared/`、`common_flags.json` 唯一源；打包时写入各工具旁 `schemas/`
- **编码**：INI 读写 UTF-8 **无 BOM**
- **发布**：GitHub Actions 构建；包名英文（`AutoReloader-MO` / `AutoReloader-YR`）；tag 触发 Release
- **配置与缓存**：可写目录持久化；外部改 ini 时缓存 fingerprint 失效
- **质量**：大功能带可手动验收清单；破坏性变更写进 Release 说明

## 5. 建议迭代节奏

1. **当前只主推 P0 性能**，完成后再开 A3 Diff 或 schema 引用类型。  
2. 每个能力合并前：主路径截图 + 简短「如何点」写进 `Frontend/editor/使用说明.txt` 或 Release note。  
3. 工坊与编辑器发版可同 tag，但 **changelog 分工具写清**。

---

## 6. 成功标准（何时算「拿得出手」）

- 新用户 5 分钟内：打开工程 → 搜到单位 → 改一处 → 保存或部署 hotfix。  
- **大工程打开有进度、树可点、不长时间假死**（P0）。  
- 高玩：能靠**引用搜索 + 校验**做完一次武器替换而不靠全库手工翻。  
- 对外演示有稳定三张图：对象树+编辑、搜索/引用、Diff 或校验结果。
