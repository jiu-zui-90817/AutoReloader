## 一、概要

v2.1.4 是一次以**数据安全与保存可靠性**为核心的修复版本。重点解决：

- CSF 写回导致语音（wave）数据丢失；
- 战术工坊高级模式部署时误删目标 INI 的节；
- 编辑器把新单位部署到已存在的 `hotfix.ini` 时失败；
- 拆分工程全量保存时删除被覆盖的旧键；
- “保存全部”无法保存新增/克隆单位，以及脏标记、关闭提示不一致；
- 打包工作流在构建期从外部地址下载并覆盖 `app.py`。

同时补充了 18 项自动化回归测试（核心逻辑 + 离屏 UI），并清理了构建链中的临时补丁方案。

## 二、修复内容

### 2.1 数据安全

- **CSF 写回保留音效数据**  
  解析与写回现在保留每个 label 的多个值块（`RTS` / `WRTS` / `STRW` 及其 wave 附加数据）。新增或克隆单位写显示名时，不再把整个 CSF 里的语音文件名清空。
- **全量保存保留被覆盖的旧键**  
  拆分工程中，同一键被后加载文件覆盖时，前一个文件中的旧副本不再被静默删除；删除键时则会同步清理**所有**来源文件，避免重载后旧值“复活”。
- **删除节 / 注册表清理保持 UTF-8 无 BOM**  
  删除节和从类型注册表移除条目改用统一的编码写入，不再把 `utf-8-sig` 的 BOM 写回工程文件。
- **备份失败中止删除**  
  删除节时若备份失败，操作会中止并提示，不再“无备份直接删”。

### 2.2 热重载部署

- **编辑器「部署到 hotfix」可追加新节**  
  当 `hotfix.ini` 已存在但还没有当前节时，按“新增”写入，不再报“拒绝写入：未找到原块”。工具栏与调试窗口行为一致。
- **「另存为」到已存在文件**  
  目标文件存在但缺少当前节时按新增追加，与界面提示文案一致。

### 2.3 编辑器保存与会话状态

- **「保存全部」支持新增/克隆单位与 Art**  
  会正确创建目标 INI、写入注册表/CSF/Art，并避免克隆 Art 重复写入或产生重复节。
- **保存失败不再清脏标记**  
  仅真正写入成功的节才从脏集合移除；失败项会保留并在结果中列出。
- **不再逐个节弹确认框**  
  「保存全部」只对实际需要写入的节生成计划，减少连续确认。
- **脏状态按标签独立跟踪**  
  保存后切回该节不再显示“未保存”；关闭程序、打开其他工程、切换配置档前会检查**所有**标签的未保存草稿。
- **「丢弃修改」真正丢弃**  
  会同时清理内存草稿、增量基线与新增/克隆的待写节，不会在之后被「保存全部」再次写回。
- **调试窗口「回写工程」**  
  改为走项目级按来源拆分写回，并保留“工程目录外拒绝写入”的守卫；不再绕过确认直接整节写单文件。

### 2.4 战术工坊

- **高级模式不再执行 hotfix 瘦身**  
  只有「安全模式 + `hotfix.ini`」才去掉与 rules 相同的键。高级模式目标可能是任意工程 INI，原先的瘦身会删除所有与 rules 相同的节（已修复）。
- **瘦身写回保持原编码**  
  不再无条件改写为 UTF-8，避免把 GBK 工程文件转码。
- **Nuitka 布局路径修正**  
  `get_app_dir()` 在 exe 位于 `Tools/_internal` 时返回 `Tools`，配置、图标与缓存位置正确。

### 2.5 解析与缓存

- **嵌套 `#include` 路径**  
  相对路径优先按当前文件所在目录解析，其次工程根目录；子目录中的二级 include 不再丢失。
- **节头行尾注释**  
  形如 `[E1] ; comment` 的节头不再被规范化成两个 `[E1]`。
- **保存不再插入空行**  
  规范化后 `[Section]` 与第一个键之间不再每次保存多出一个空行。
- **显示名缓存指纹**  
  指纹包含所有 `#include` 文件与主文件，外部修改拆分文件后缓存会正确失效。
- **注册表查重**  
  `+=ID` 的重复检测改为大小写不敏感，符合游戏 ID 语义。

### 2.6 构建与发布

- **移除构建期外部下载**  
  PyInstaller 备份工作流与 Nuitka 正式工作流都不再从外部 raw 地址下载并覆盖 `Frontend/workshop/app.py`，也删除了 `scripts/patch_workshop_icon.py`。
- **路径修复入库**  
  原先由构建期补丁写入的 `_prefer_tools_dir` 逻辑已直接提交到 `Frontend/workshop/app.py`，源码与发布产物一致。
- **启动器健壮性**  
  MO 启动器检查 `CreateToolhelp32Snapshot` 失败，避免无效句柄继续调用。

## 三、行为变化与升级注意

1. **「保存全部」只保存有未保存修改的标签**  
   未修改的标签不会再被重写；写入更快、diff 更少。
2. **高级模式部署不再自动瘦身**  
   写入目标 INI 时会保留全部键；需要瘦身请使用安全模式的 `hotfix.ini`。
3. **删除键会作用于所有来源文件**  
   拆分工程中同名节的多份副本会被一起清理，这是为了删除语义正确。
4. **CSF 写回方式变化**  
   新版本保留已有音效块。若你曾使用旧版本写过显示名并怀疑语音丢失，请从工程/程序目录的 `backups/` 中恢复对应 `.csf` 备份（每次写入前都会备份）。
5. **关闭/切换工程会检查所有标签**  
   有多个标签存在未保存草稿时，会统一提示“保存全部 / 丢弃 / 取消”。

## 四、兼容性

- INI 读写仍为 **UTF-8 无 BOM**；原本是 GBK 的文件保持 GBK。
- `config.json`、`profiles.json`、`ReloaderConfig.ini`、`hotfix.ini` 格式不变。
- DLL 注入方式、启动器用法、`Tools/` 目录结构不变。
- CSF 写回仍保持原 CSF 的 version / language；常规 `RTS`、`WRTS`、`STRW` 值块可保留。

## 六、已知限制

- 热重载仍只能重载**已在内存中存在**的类型；新增类型需正常注册并重启。
- 高级模式部署不自动清理与 rules 相同的键（这是安全权衡）。
- CSF 写回保留已解析的标准值块；非常规 CSF 扩展块未做通用支持。
- 本说明对应源码提交；正式发布包仍需由 `Build Nuitka Release` 工作流（tag `v*-nuitka`）构建。
